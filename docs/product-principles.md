# Product principles

1. **One screen, one question.** The first screen answers one understandable financial question instead of exposing a configurable BI workspace.
2. **Evidence stays visible.** Series, observed range, retrieval timestamp, unit, and primary-source link are part of the product surface.
3. **Python owns meaning.** Financial transformations live in `code/static_bi.py`; JavaScript owns interaction and rendering.
4. **No live-data theater.** A committed snapshot is never presented as a current market value.
5. **Fun means immediate feedback, not decoration.** Interaction should produce an understandable visual and textual answer without onboarding.
6. **Accessibility is architecture.** Keyboard access, visible focus, target size, reduced motion, responsive layout, and semantic status are baseline requirements.
7. **Dependencies need a measured reason.** Add an analytical runtime only when the current data/interaction model can no longer meet the product contract simply.
